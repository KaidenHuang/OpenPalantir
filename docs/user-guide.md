# 使用说明 | User Guide

## 1. 安装与启动

### 环境要求

| 组件 | 最低版本 | 推荐版本 |
|------|---------|---------|
| Python | 3.10 | 3.11+ |
| Node.js | 18 | 20+ |
| Neo4j | 4.4 | 4.4.8+ |
| Redis | 6.0 | 7.0+ |
| Debezium Server | 3.5.2 | 3.5.2.Final（可选，用于 CDC 增量同步） |

### 方式一：Docker 部署（推荐）

```bash
# 1. 克隆仓库
git clone https://github.com/your-org/OpenPalantir.git
cd OpenPalantir

# 2. 配置环境变量
cp backend/.env.example backend/.env
# 编辑 backend/.env，至少修改 NEO4J_PASSWORD

# 3. 一键启动
docker-compose up -d

# 4. 访问
# 前端: http://localhost:5175
# API 文档: http://localhost:8000/docs
```

### 方式二：手动安装

```bash
# 1. 安装 Neo4j 和 Redis
# 下载 Neo4j Community 4.4: https://neo4j.com/download/
# 下载 Redis 7: https://redis.io/download/

# 2. 安装 Debezium Server（可选，用于数据库增量同步）
# PowerShell: scripts/install/install-debezium.ps1

# 3. 后端
cd backend
cp .env.example .env
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# 4. 前端
cd frontend
npm install
npm run dev

# 5. 访问 http://localhost:5175
```

### 配置说明 (`backend/.env`)

```ini
# Neo4j (必配)
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=你的密码

# Redis
REDIS_HOST=localhost
REDIS_PORT=6379

# LLM API 密钥 (可选，不配则使用本地 Ollama)
OPENAI_API_KEY=
SILICONFLOW_API_KEY=
DEEPSEEK_API_KEY=
```

## 2. 功能使用指南

系统包含 9 个功能标签页，从左到右依次使用构成完整的分析链路。

### 2.1 文档管理

**场景**：你有大量文档（小说、论文、企业文件），希望从中提取人物关系、事件脉络。

**操作步骤**：

1. 进入「文档管理」标签页
2. 点击「添加文档源」，选择文件或目录
3. 选中文件 → 点击「生成概要」，系统自动执行：
   - 解析文档内容（支持 PDF/Word/Markdown/TXT/图片OCR）
   - 生成多层级摘要树（左侧面板可浏览）
4. 选择**本体域**（与「生成概要」「提取实体关系」同排的下拉框，内置 general/workforce/finance/medical，导入社区包后一并出现）→ 点击「提取实体关系」（需先生成概要，否则按钮置灰）
   - 该域的词表会被注入抽取 prompt，决定 LLM 能用哪些实体类型与关系谓词
   - 抽取产出的谓词先归一化到受控词表，再以类型化边写入图谱
5. 处理后可在「实体管理」「图谱可视化」「知识Wiki」查看结果

**支持的格式**：

| 格式 | 说明 |
|------|------|
| .txt | 纯文本 |
| .pdf | PDF 文档 |
| .docx | Word 文档 |
| .md | Markdown 文件 |
| .jpg/.png/.bmp | 图片（OCR 识别） |

**文档更新后**：改动源文件会让该文档的摘要、图谱与 Wiki 数据过期。两条路径重跑「摘要 → 回收本来源旧实体 → 重新抽取 → 刷新 Wiki」一条链：

- 手动：`POST /api/sources/{source_id}/refresh`，body `{"file": "相对路径"}`（异步任务，UI 暂未提供按钮）
- 自动：设 `DOC_WATCH_ENABLED=1`，后端按 `DOC_WATCH_INTERVAL`（默认 60 秒）轮询内容指纹并自动派发刷新任务；监听派发固定使用 `general` 域

### 2.2 数据库管理

**场景**：你已有结构化数据库（MySQL/PostgreSQL/SQLite），希望将其导入图谱进行分析。

**操作步骤**：

1. 进入「数据库管理」标签页
2. 点击「添加连接」，填写：
   - 连接名称、数据库类型（MySQL/PostgreSQL/SQLite）
   - 主机地址、端口、用户名、密码、数据库名
3. 点击「测试连接」验证
4. 连接成功后，选择目标数据库 → 点击「分析 Schema」
5. 系统会用 LLM 自动标注每列的业务含义
6. 选择需要导入的表 → 点击「导入图谱」
7. 等待异步任务完成，数据即进入图谱

**支持的数据源**：
- MySQL 5.7+（需开启 binlog）
- PostgreSQL 12+（需配置逻辑复制）
- SQLite 3

**实体命名**：数据库行实体以 `{表名}:{主键值}` 命名，如 `employees:1001`。

**标注词表与本体域**：「分析 Schema」的 LLM 标注使用与文档抽取同一套受控词表。当前 UI 走默认域 `general`；需要按领域标注时调接口传 `domain`：

```bash
POST /api/database/connections/{id}/analyze
{"database": "mydb", "domain": "workforce"}
```

**增量同步（CDC）**：

全量导入完成后，可开启基于 Debezium 的增量同步，实时捕获源数据库的变更（INSERT/UPDATE/DELETE）并自动同步到图谱。

开启方式（API 调用）：
```bash
# 全量导入时自动启动 CDC
POST /api/database/connections/{id}/import?auto_start_cdc=true

# 或手动启动
POST /api/cdc/{connection_id}/start
Body: {"database_name": "mydb"}
```

增量同步特性：
- 支持 MySQL（binlog）、PostgreSQL（WAL）、Oracle、SQL Server
- 全量导入与增量同步无缝衔接，使用相同的实体 ID 方案
- 支持断点续传，进程重启后从上次消费位点继续
- 启动前自动检测事件流连续性，发现间隙时提示重新全量导入

### 2.3 实体管理

**场景**：浏览、搜索、编辑系统中所有的实体。

**功能**：

- **搜索**：按名称模糊搜索，支持按类型过滤（人物/组织/地点/事件/概念）
- **查看详情**：点击实体查看其属性、关联关系
- **编辑**：修改实体名称、类型、描述、自定义属性
- **删除**：删除实体及其所有关联关系

### 2.4 图谱可视化

**场景**：以可视化方式探索知识图谱。

**功能**：

- **2D 力导向图**：节点=实体，连线=关系。支持拖拽、缩放、悬停高亮
- **3D 视图**：通过 react-force-graph-3d 展示立体图谱
- **交互**：
  - 点击节点查看详情
  - 点击边查看关系
  - 自由拖拽节点调整布局

---

### 2.5 分析引擎

**场景**：对图谱进行结构化分析，获取深层洞察。

#### 路径分析
- 输入：起始实体 A → 目标实体 B
- 输出：两者之间的最短路径（经过的节点序列）

#### 社区发现
- 使用 Louvain 算法自动检测图谱中的社区结构
- 输出：各社区包含的节点数、模块度评分

#### 中心性分析
- 支持多种中心性指标：
  - **度中心性**：连接数最多的节点
  - **介数中心性**：信息流动的关键"桥梁"节点
  - **特征向量中心性**：与重要节点相连的节点
  - **PageRank**：类似 Google 排名的权威节点

#### 趋势分析
- 分析实体的时间分布趋势

#### 报告生成
- 将分析结果导出为 HTML 报告

### 2.6 智能决策

**场景**：用自然语言提问，系统结合图谱 + 数据库 + 文档为你提供决策建议。

**操作步骤**：

1. 进入「智能决策」标签页
2. 在输入框中输入问题，如：
   - "分析当前组织中的人员分布"
   - "最近一周有哪些重要事件？"
   - "人物 A 和人物 B 之间有什么关联？"
3. 系统返回结构化回答：
   - **摘要**：简明结论
   - **态势分析**：背景和现状
   - **关键问题**：需要注意的风险点
   - **方案选项**：可选应对方案
   - **建议**：推荐方案
   - **工单**：可执行的任务清单

**Agentic RAG**：系统采用统一的 Agentic RAG 模式，AI 助手会根据您的问题自动检索图谱、文档和数据库中的相关信息，通过多轮工具调用收集证据，最终给出结构化的决策建议。每次回答附带置信度评估（0.0–1.0），低置信度答案会标记为需人工复核。

**本体域**：标题栏右侧的下拉框选择问答使用的本体域（词表来自本体注册表，社区导入的域无需重启即可选到）。实体类型词表影响问题解析，选错域会让检索偏离目标类型。

**引用与作用域**：回答附带证据引用（`citations`），每条可点击跳回原文所在摘要节点；从 Wiki 页面点「就本页提问」会把该页面作为 `scope` 带过来，回答只依据本页内容。

**沉淀为页面**：满意的回答可一键发布为新的 Wiki 页（`kind=answer`，保留引用），使问答结论变成可继续编辑的内容资产。

### 2.8 模型管理

**场景**：配置 LLM 模型，系统的实体提取、Schema 标注、决策推理都需要 LLM。

**操作步骤**：

1. 进入「模型管理」标签页
2. 系统预置了五个模型配置：
   - **Ollama**：本地模型（需安装 Ollama，默认 http://localhost:11434）
   - **OpenAI**：云端模型（需提供 API Key）
   - **DeepSeek**：云端模型（需提供 API Key）
   - **硅基流动**：云端模型（需提供 API Key）
   - **OpenRouter**：云端模型聚合网关（需提供 API Key，默认 https://openrouter.ai/api/v1，模型 ID 形如 `minimax/minimax-m3.1-flash:free`；预置的三个均为 `:free` 模型，账号无余额也可调用）
3. 配置正确的 API URL 和密钥
4. 点击「测试连接」验证
5. 启用需要使用的模型

**模型类型**：
- **本地**：通过 Ollama 运行，数据不出本地，适合隐私敏感场景
- **云端**：通过 OpenAI-compatible API 调用，速度快，适合对延迟敏感的场景

### 2.9 知识Wiki

**场景**：把散落在多篇文档里的知识自动重组成可编辑、带引用、能继续沉淀的 Wiki 页面，而不是只留下一棵只能看的摘要树。

**页面类型**：

| 类型 | 生成依据 | 说明 |
|------|---------|------|
| 文档页 | 单个文件的层级摘要树 | 以摘要节点为单位聚合改写 |
| 主题页 | 多篇文档的同主题节点 | LLM 跨文档改写，不是拼接 |
| 实体页 | 图谱中实体的全部关系 | 谓词来自所选本体域的词表 |
| 问答沉淀 | 智能决策的优质回答 | 保留原引用，可继续编辑 |

**操作步骤**：

1. 进入「知识Wiki」标签页；首次为空时提示「暂无 Wiki 页面，点击「生成全部」从文档摘要创建。」
2. 左上角三个按钮：「生成全部」「仅主题页」「仅实体页」，任务异步执行，界面每 3 秒轮询进度（也可在「任务管理」查看）
3. 左侧列表按类型分组，未发布的页面标橙色「草稿」
4. 打开页面 →「编辑」进入 Markdown 文本域 →「保存」或「取消」；草稿页可点「发布」置为已发布

**引用溯源**：每页正文自动附加「参考来源」小节，正文中的 `[n]` 编号渲染为上标，对应摘要树节点或图谱实体。

**相关页面**：页面底部列出由实体提及与图谱关系推导出的 wiki-link。

**就本页提问**：文档页右上角的「就本页提问」会跳转到「智能决策」并把该页作为 `scope` 带过去，回答只依据本页内容。

**从图谱生成实体页**：「图谱可视化」中右键节点 →「查看实体页」，自动提交该实体的页面生成任务，完成后直接打开页面；若该实体未产出页面会给出提示。

**失效与回收**：刷新文档时，该来源的页面会重生成，主题页/实体页按内容指纹重算，摘要文件或图谱实体已消失的页面会被自动清理，不会留下无依据的旧页面。

## 3. 注意事项

1. **首次使用建议**：
   - 先配置至少一个 LLM 模型（推荐本地 Ollama + qwen2.5:7b）
   - 用小文档测试完整流程
   - 再导入大批量数据

2. **性能建议**：
   - 大批量文档处理建议分批进行
   - 数据库导入单表上限 1000 行
   - 图谱节点超过 10 万时建议启用分区功能

3. **数据安全**：
   - 云端模型会将数据发送到外部 API，敏感数据请使用本地 Ollama
   - `.env` 文件中的密钥请勿提交到版本控制（已加入 `.gitignore`）
